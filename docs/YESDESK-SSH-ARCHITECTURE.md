# YES Desk SSH Terminal

SSH Terminal — настольный модуль YES Desk. Вкладка открывает собственный
TCP-сокет непосредственно к указанному SSH-серверу. Транспорт RustDesk,
прежний терминал RustDesk, FFI, диспетчер удалённых рабочих столов и
пакеты установки работают по существующим путям. SSH не использует
hbbs, hbbr или rustdesk-api.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `models/ssh_profile.dart` | UUID, адрес и порт, пользователь, метод входа, группа, комментарий, избранное и настройки терминала |
| `storage/ssh_repository.dart` | Профили, группы, отдельное хранилище доверенных ключей, атомарная замена JSON под блокировкой |
| `storage/ssh_secrets.dart` | Интерфейс системного хранилища и Windows Credential Manager под текущим пользователем |
| `services/ssh_transport.dart` | Прямой SSH 2.0, host key, аутентификация, PTY, потоковый ввод-вывод и тайм-ауты |
| `controllers/ssh_tab.dart` | Отдельные транспорт и xterm-буфер на вкладку, размеры PTY, имя и текущий размер шрифта |
| `pages/` и `widgets/` | Навигация, каталог, вкладки, поиск в буфере, безопасная вставка |

Компоненты находятся в `flutter/lib/yesdesk/ssh/`. Переключение страниц и
вкладок сохраняет активные подключения. Страница наследует тему и выбранный
язык рабочего пространства. Палитра терминала задаётся в профиле независимо
от темы приложения.

Профили и группы хранятся в `ssh/profiles.json` в каталоге данных приложения
для текущего пользователя. Группы представлены папками одного уровня, включая
пустые папки. Секреты записываются только по явному выбору пользователя. JSON
содержит ссылку на запись хранилища. Приватный ключ читается из выбранного файла
и не копируется в каталог YES Desk. В Windows можно сохранить пароль или путь
к ключу и его passphrase в Generic Credential. На остальных настольных
платформах, а также при ошибке Windows Credential Manager, секрет вводится
для одной попытки подключения. Изменение адреса, порта, логина или метода
входа отвязывает прошлую запись. Dart не гарантирует затирание всех копий
строк в памяти.

## Движок и совместимость

Приложение использует Flutter 3.24.5 и существующий `xterm 4.0.0`.
`dartssh2 2.11.0` совместим с закреплённым `meta`, но предшествует строгому
обмену ключами против Terrapin (CVE-2023-48795) и проверкам при rekey из 4.0.0.
Версия 4.1.0 включает эти изменения, проверку публичных значений KEX,
сравнение MAC за постоянное время и исправления буферизации канала.
Архив 4.1.0 закреплён как локальная MIT-зависимость. Исходники движка
соответствуют архиву. В манифесте понижена нижняя граница `meta` до 1.12.0
для Flutter 3.22.3, который использует существующая генерация FFI. Все
используемые аннотации доступны в 1.12.0. Во Flutter 3.24.5 resolver
сохраняет `meta 1.15.0`.
[Архив и патч](../flutter/third_party/dartssh2/UPSTREAM.md) ·
[История изменений](https://pub.dev/packages/dartssh2/versions/4.1.0/changelog)

Профиль алгоритмов предлагает Curve25519, NIST ECDH и DH с SHA-256,
ключи сервера Ed25519, ECDSA и RSA SHA-2, AES-GCM или AES-CTR и SHA-2 MAC.
SHA-1, CBC и ChaCha20-Poly1305 исключены из предложений модуля.
Форматы ключевых файлов определяет парсер движка. OpenSSH Ed25519 и
шифрованные OpenSSH PEM являются приоритетными форматами. PuTTY PPK,
OpenSSH host certificates и импорт `known_hosts` вне границ спринта.

## Доверие и жизненный цикл

Ключи привязаны к нормализованному адресу и TCP-порту в
`ssh/known-hosts.json`. DNS-имя и IP считаются отдельными адресами. Клиент
проверяет подпись сервера и передаёт в обязательный callback алгоритм и
OpenSSH SHA256 fingerprint. Успешная проверка предшествует сетевой
аутентификации. В режиме ключевого входа файл может быть прочитан локально
перед подключением. При первом соединении пользователь сверяет отпечаток
и принимает или отклоняет ключ. При несовпадении соединение блокируется.
После сверки смены ключа с администратором пользователь может отдельным
действием удалить старое доверие. Следующее подключение снова требует
явного принятия ключа.

Попытка проходит состояния подключения, проверки ключа, аутентификации,
активной сессии и закрытия. TCP, сетевой обмен и запрос PTY ограничены
тайм-аутом профиля. Диалог ожидает ответ до двух минут. Отмена закрывает
сокет и диалоги текущей попытки. Переподключение создаёт новые TCP, SSH и
PTY и снова проверяет ключ. При запуске запрашивается PTY
`xterm-256color` и интерактивный shell. Ввод поступает от пользователя и
терминального эмулятора.

У stdout и stderr отдельные декодеры UTF-8. Контроллер передаёт вывод в
xterm небольшими пакетами и приостанавливает чтение при накоплении.
Максимум строк задаёт профиль. OSC 52 не подключён к системному буферу.
Маршруты вставки проходят через один диалог для текста с переносами
строк. Пароли, ключи, ответы на запросы и вывод терминала не передаются
обработчикам логирования. Ошибки представлены локализованными категориями.

## Точки расширения

- SFTP может запрашивать отдельный канал после проверок доверия и
  аутентификации. Файловые операции и жизненный цикл канала принадлежат SFTP.
- Bastion и SSH port forwarding могут получить отдельные реализации
  сокетного адаптера. Для каждого SSH-узла необходима самостоятельная
  проверка его ключа.
- Split terminal может комбинировать несколько вкладочных контроллеров
  без общего PTY или буфера. Сохранённые команды могут отправляться через
  обычный пользовательский ввод по явному действию.
- Общий каталог может ссылаться на UUID SSH-профиля и хранить тип модуля.
  Ссылки на локальные секреты остаются в соответствующем хранилище.
