# Проверка YES Desk SSH Terminal

Подготовьте Flutter 3.24.5 и выполните из `flutter/`:

```bash
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib/yesdesk/ssh lib/common/widgets/peer_tab_page.dart test/yesdesk_ssh
flutter analyze --no-pub lib/yesdesk/ssh test/yesdesk_ssh
flutter analyze --no-pub --no-fatal-infos lib/common/widgets/peer_tab_page.dart
flutter test --no-pub
```

На Linux с `sshd`, `ssh-keygen`, Python 3 и OpenSSL выполните из корня проекта:

```bash
scripts/test-yesdesk-ssh-openssh.sh
```

Сценарий создаёт два сервера на loopback, временный аккаунт и ключи хостов.
Для создания и удаления аккаунта требуется root или `sudo -n`. Запуск
с `--handshake-only` проверяет отпечаток, отклонение, несовпадение,
отмену и отказ при неверной фразе ключа. Проверки пароля и PTY выполняются
в полном режиме. Обычный `flutter test` пропускает сценарии OpenSSH
вне стенда.

## Ручная проверка

1. Запустите Windows portable EXE и MSI из артефакта `YES_Desk-Flutter-x64`.
   Откройте SSH Terminal, вернитесь к устройствам и убедитесь, что SSH
   продолжает работать. Переключите русский и английский языки, светлую,
   тёмную и системную темы. Откройте профиль со светлой палитрой терминала.
2. Создайте группу и два профиля, добавьте один в избранное, найдите его
   по имени и отредактируйте комментарий. Перезапустите программу и
   проверьте сохранение каталога.
3. Сверьте отпечаток с выводом `ssh-keygen -lf <host-key.pub>` на стенде.
   Проверьте отказ, принятие и повторный вход. Замените ключ стенда и
   убедитесь, что отображаются оба отпечатка, а вход блокируется.
   Удалите старую запись и проверьте, что новое соединение требует согласия.
4. Войдите по паролю, ключу с passphrase и keyboard-interactive.
   Проверьте неверные данные, отмену и повторный запуск с сохранёнными
   данными. Проверьте удаление записи через редактирование профиля.
   В JSON остаются ссылки на Windows Credential Manager. В логах
   не должно быть секретов и вывода терминала.
5. Используйте две сессии одного профиля во время вывода. Проверьте Ctrl+C,
   Ctrl+D, Tab, Escape, стрелки и F-клавиши в Vim, Nano и htop. Проверьте
   resize, выделение, поиск, очистку, Ctrl+Shift+C и Ctrl+Shift+V. Вставка
   нескольких строк требует подтверждения. Проверьте, что вывод OSC 52
   на стенде оставляет локальный буфер обмена без изменений.
6. Отклоните подтверждение закрытия, затем закройте вкладку. Вторая сессия
   продолжит работу. Остановите стенд и проверьте разрыв и переподключение.
7. Между согласованными тестовыми клиентами проверьте Remote Desktop, видео,
   ввод, буфер обмена и исходный терминал RustDesk. Установите MSI из portable
   и запустите удаление через Windows Settings.
