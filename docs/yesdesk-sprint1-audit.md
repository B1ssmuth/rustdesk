# YES Desk 2.0 Sprint 1 audit

Recorded on 2026-11-20 for `B1ssmuth/rustdesk`, branch `feature/yesdesk-2.0`.

## Baseline and architecture

- The clean starting HEAD was `c241a232195e070855218405aab6a0a93468c1d8`. Comparing it with the Sprint 1 base `67289830ea4a1a08fc6023360d0ab5cdf3d73796` showed only the two planning documents. The fetched upstream comparison commit `cca6a5fe12570d7a65f1b8eb7485a1c865dcd859` differed across 55 paths, counting the planning documents and the replacement of the `hbb_common` gitlink. [Upstream comparison](https://github.com/rustdesk/rustdesk/commit/cca6a5fe12570d7a65f1b8eb7485a1c865dcd859)
- Cargo declares package `rustdesk` 1.4.6, library `librustdesk`, and Rust 1.75. Flutter declares `flutter_hbb` 1.4.6+64 and Dart ^3.1.0. Windows CI selects Flutter 3.24.5, LLVM 15.0.6 and Rust 1.75 for x64. The shared bridge job selects Flutter 3.22.3, uses an `extended_text` 13.x build-time override and runs `flutter_rust_bridge_codegen` 1.80.1. Dart uses `flutter_rust_bridge` 1.80.1 and Rust pins 1.80.0. The Flutter lockfile resolves pub.dev packages and Git dependencies including the window manager, multi-window and texture rendering plugins.
- Desktop launch in `flutter/lib/main.dart` initializes native FFI, providers and the window controller. The new home mounts beneath the existing window tabs. ID and temporary password come from `ServerModel`. The connection footer reads `mainGetConnectStatus` and quick connect calls `connect` in `common.dart`, which uses the bridge for relay-ID handling and the existing desktop session dispatcher. Incoming prompts and consent continue through the connection manager and service. Discovery, recents, favorites, address book and accessible devices keep the existing peer models, refresh, selection and context actions.
- Cargo uses `libs/hbb_common` as a vendored path dependency. Upstream pinned it to gitlink `f08ce5d6d07cd200713418ce2932769d14ff21d2`. A recursive comparison with an archive of that commit found one differing file, `src/config.rs`, with four changed lines for product defaults. The protocol definitions match that archive. [Upstream hbb_common pin](https://github.com/rustdesk/hbb_common/commit/f08ce5d6d07cd200713418ce2932769d14ff21d2)
- Client options and persistence live in `libs/hbb_common/src/config.rs`. Default server resolution also uses `src/common.rs`. The fork already supplies product-specific rendezvous, API and public-key defaults. `mainIsUsingPublicServer` is a legacy check for an empty custom-server resolution, so it cannot identify the deployed SCTGDesk variant. Explicit ID suffix and server override handling remain in the existing path. Deployment version, relay behavior, authentication and API extensions require a sanctioned test instance.
- Windows CMake builds `rustdesk.exe` and bundles `librustdesk.dll`. The x64 workflow calls `python3 build.py --portable --hwcodec --flutter --vram --skip-portable-pack`, stages a second executable as `YES_Desk.exe`, patches MSI source names in the runner checkout, invokes `preprocess.py --arp`, and runs NuGet and MSBuild. The portable packer launches the staged YES Desk executable. vcpkg supplies the native codec libraries. The runner declares PerMonitorV2 DPI awareness and the portable step modifies its own manifest. The naming, CMake, manifests and package commands are retained.

## Findings and changes

- The manual Windows workflow previously enabled release publication by default, and its release steps accepted feature refs. Manual publishing now defaults off. Both release steps additionally require `master` or a matching non-nightly tag. `Full Flutter CI` uses a read-only contents token and passes the publication flag as false. It still uploads Windows EXE/MSI workflow artifacts. The asset upload now fails if the expected path contains no files. Updated Node 16-era GitHub Script and release actions to their Node 20 versions and removed unused signing-secret environment variables.
- References such as the custom Flutter engine release, driver asset and several third-party actions can change upstream. The vcpkg revision and the topmost-window source revision are pinned. Record hashes for downloaded components before adopting a reproducible distribution pipeline.
- A cross-window debug line included the full IPC argument object, which can carry session credentials. Main-window logging now keeps the method and sending window. The IPC contract remains in use.
- Quick connect previously kept two text controllers, and its loading UI used a synthetic peer in autocomplete. The workspace uses the production ID formatter, one controller, real suggestions and the existing connection dispatcher. The saved ID initialization checks that the input is still empty. Search focus and the peer refresh subscription are disposed with their widgets.
- Graphite and light palettes are scoped to the home workspace. The main pane combines quick connect and a keyboard-accessible device navigation rail. Preferred list or tile styles and managed tab visibility are honored. A new workspace starts with the compact list view. Credential copy and regeneration use the real model and bridge. On narrow windows the support pane opens from the header while preserving the connection field. Mobile retains its existing peer tab presentation.
- The old `test/cm_test.dart` was a desktop manual demo with an outdated `Client` constructor and a test-incompatible entry point. It now lives at `flutter/tool/connection_manager_demo.dart` with the current constructor. The lockfile reflects SDK pins introduced by the `flutter_test` development dependency.
- The AGPL-3.0 license and notices, installer identity and SCTGDesk connection contracts are retained. Rust edits are confined to translation catalogs.
