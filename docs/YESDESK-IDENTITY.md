# YES Desk Sprint 1.1 — визуальная идентичность

База изменений — `feature/yesdesk-2.0` на `a7db86e`. В Sprint 1 пользователь подтвердил установку MSI, запуск, подключение нового клиента к старому, изображение и обмен через буфер. Остальные сценарии, включая обновление этой версии поверх Sprint 1, требуют проверки на Windows.

## Источники стиля и права

Публичный сайт YES Apart содержит тёплую нейтральную палитру, светлые инверсные поверхности, простые геометрические блоки и выраженную типографическую иерархию. Для рабочего пространства использованы цвета CSS сайта, включая `#322d29`, `#4d4743`, `#575757`, `#918882`, `#cfc8c3`, `#d6d6d6`, `#f3f3f3`, белый и светлый `#f8e7db`. Роли фона, текста, выделения, фокуса и ошибок подобраны для обеих тем. [YES Apart](https://yesapart.com/) · [Стили сайта](https://yesapart.com/assets-dark-theme/stylesheets/global.css)

Сайт использует TT YesType для заголовков, Suisse Int для текста и варианты знака YES для разных поверхностей. Публичная загрузка этих файлов не подтверждает право на распространение шрифтов и фирменного знака в приложении. Дистрибутив использует типографику Flutter с системными fallback и собственную геометрическую пиктограмму рабочего монитора. Исходник пиктограммы находится в `flutter/assets/icon.svg`, а PNG, ICO, macOS template icons и BMP установщика созданы для проекта. Изображения сайта в сборку не входят. [Публичный знак YES Apart](https://yesapart.com/assets-dark-theme/images/icons/YES_logo.svg)

## Совместимость Windows Installer

Из собранного MSI Sprint 1 извлечены таблицы `Property`, `File`, `Registry`, `Directory`, `Shortcut`, `CustomAction` и Summary Information. Старый пакет содержит `ProductName=RustDesk`, `Manufacturer=PURSLANE`, `App.exe=RustDesk.exe` и `UpgradeCode={D3DC41E3-3C37-5D52-BB47-F6673705C01B}`. Служебное действие использует имя `RustDesk` и `[INSTALLFOLDER_INNER]RustDesk.exe`. [Артефакт Sprint 1](https://github.com/B1ssmuth/rustdesk/actions/runs/44715109869/artifacts/14622375164)

В новой цепочке `--display-name` влияет только на публичное имя. `--app-name` по-прежнему задаёт WiX-идентичность и формулу UUIDv5 для того же UpgradeCode. Существующий механизм генерации ProductCode в WiX сохранён. `Product.Registry.*`, ID компонентов, путь Program Files, служба и запись деинсталляции относятся к технической миграции и сохраняются. Широкая подстановка в PowerShell заменена целевыми переменными и токеном локализации. Это также предотвращает искажение технического имени `RuntimeBroker_rustdesk.exe` при препроцессинге. Сравнение MSI следует выполнять до теста обновления на VM.

Поля нового MSI для проверки включают `Property.ProductName`, `Manufacturer`, `UpgradeCode`, `File.App.exe`, имена ярлыков и службы, отображаемые значения Registry, шаблон Summary Information `x64;1033` и таблицы `Icon` и `Binary`. Тестовая сборка использует **Full Flutter CI** и публикует артефакт `YES_Desk-Flutter-x64`.

## Карта изменений

- Тема и компоненты находятся в `flutter/lib/yesdesk/{theme,widgets,identity}.dart`. Подключение темы выполняется в `flutter/lib/{main,common}.dart`.
- Основные desktop-экраны находятся в `flutter/lib/desktop/pages/`. Вкладки и меню находятся в `flutter/lib/desktop/widgets/`. Представления устройств и адресной книги используют `flutter/lib/common/widgets/{peer_tab_page,peer_card,peers_view,address_book}.dart`.
- Локализация добавлена в `src/lang/{en,ru,template}.rs`. Тесты находятся в `flutter/test/yesdesk_workspace_test.dart`.
- Ресурсы Windows и упаковки находятся в `flutter/windows/runner/`, `libs/portable/Cargo.toml`, `res/msi/` и `res/`. `.github/workflows/flutter-build.yml` передаёт отдельное отображаемое имя в препроцессор.
- Текущий сервер и дизайн SSH вынесены в [серверную архитектуру](YESDESK-SERVER-ARCHITECTURE.md) и [архитектуру SSH](YESDESK-SSH-ARCHITECTURE.md). Полный список файлов выдаёт `git diff --name-status a7db86e..HEAD`.

## Проверки

Локально выполнены девять Flutter-тестов. Они покрывают RU/EN, светлую, тёмную и системную темы, масштабирование 100/125/150% на уровне Flutter, изменение ширины таблицы, клавиатуру и контраст. Flutter debug bundle собран с реальными Dart FFI. Полный `flutter analyze --no-pub` завершился без ошибок с пятью известными предупреждениями из Sprint 1. Сборка ZIP и проверка нативного MSI выполняются в Windows CI и после загрузки артефакта.

В Linux CI прошлого спринта `wl-clipboard-rs 0.9.0` не выводил тип результата `collect()` на новом stable Rust. Закреплён Rust 1.91.1 только в Linux CI, без изменения lockfile и параметров сборки. `cargo +1.91.1 check --locked -p wl-clipboard-rs` прошёл. Предупреждение о будущей несовместимости остаётся. Перейти на актуальный Rust можно после отдельного обновления Wayland-зависимостей. [Трассировка изменения Rust](https://github.com/rust-lang/rust/issues/148922) · [Исправление в upstream](https://github.com/YaLTeR/wl-clipboard-rs/commit/28b0ca4ce64c9641db1ac8a932569777f675c053)

Две попытки Windows x64 остановились на HTTP 503 при загрузке уже закреплённого патча `mfx-dispatch`. Проверенное изменение из исходного патча перенесено в локальный overlay vcpkg. Версия порта и итоговая правка исходника остались прежними. [Патч upstream](https://github.com/lu-zero/mfx_dispatch/commit/d6241243f85a0d947bdfe813006686a930edef24) · [Первые попытки Windows CI](https://github.com/B1ssmuth/rustdesk/actions/runs/44727409666)
