# Проверка «Моих подключений»

## Локальные тесты

Используйте Flutter 3.24.5 из текущего desktop CI.

```sh
cd flutter
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib/yesdesk/connections lib/yesdesk/ssh lib/yesdesk/rdp lib/common/widgets/peer_tab_page.dart lib/utils/multi_window_manager.dart test/yesdesk_connections
flutter analyze --no-pub --no-fatal-infos lib/yesdesk/connections lib/yesdesk/ssh lib/yesdesk/rdp lib/common/widgets/peer_tab_page.dart lib/utils/multi_window_manager.dart test/yesdesk_connections
flutter test --no-pub --reporter expanded
cd ..
rustfmt --edition 2021 --check src/flutter_ffi.rs
```

Для изолированного OpenSSH на Linux выполните тесты существующей интеграции и контракт каталога с теми же контейнерами. Для базового SSH-набора без системного тестового пользователя используйте `--handshake-only`. Для контейнерной сборки за HTTPS-прокси существующий скрипт принимает системный доверенный CA через `YESDESK_SFTP_CA_BUNDLE`.

```sh
scripts/test-yesdesk-ssh-openssh.sh --handshake-only
scripts/test-yesdesk-sftp-openssh.sh test/yesdesk_connections/adapter_test.dart
```

Тесты с контейнером проходят путь `ConnectionRepository → ConnectionLauncher → SshWorkspace → OpenSSH` для терминала и проводника. RDP-контракт проверяет содержимое временного файла, фактический запуск/завершение дочернего процесса, очистку файла и ошибку штатного launcher на Linux. Штатный MSTSC и нативная ветка RustDesk требуют интерактивной проверки ниже.

## Проверка в desktop-сборке

1. Откройте приложение с сохранёнными peers, избранным, недавними устройствами, RDP-профилем и SSH-профилем в группе. Откройте «Мои подключения», зафиксируйте число записей и перезапустите приложение. Убедитесь, что одна и та же запись текущего RustDesk peer не повторяется из-за наличия одновременно в истории и избранном. Сверьте профили и группы с исходными рабочими областями.
2. Создайте папку, внутри неё ещё две папки. Попробуйте переместить родителя внутрь потомка. Убедитесь, что такой пункт отсутствует. Создайте, отредактируйте, продублируйте, закрепите и удалите профиль в глубокой папке. Проверьте поиск сочетанием имени, адреса, типа и тега, фильтр избранного и сортировку.
3. Выберите профиль одним кликом, запустите двойным кликом или через контекстное меню. Нажмите Ctrl+F для поиска, Ctrl+N для создания, Ctrl+Enter для запуска выбранной записи, F2 для редактирования и Esc для закрытия деталей. Переключите таблицу и плитки.
4. Откройте тестовый RustDesk peer и вернитесь в «Мои подключения». Проверьте состояние «Открыта вкладка», затем закройте удалённую вкладку и дождитесь обновления. Проверьте те же действия с SSH и SFTP. Вернитесь в каталог, закройте детали и убедитесь, что терминал и проводник сохранили свои сессии.
5. На Windows запустите сохранённый профиль RDP, подтвердите открытие штатного MSTSC, проверку сертификата и системный запрос учётных данных. Проверьте, что каталог учитывает только процесс, который запустил клиент. На Linux или macOS попробуйте открыть такой же профиль и проверьте локализованную ошибку платформы.
6. Сохраните тестовые учётные данные SSH на Windows. Продублируйте профиль, создайте отдельный SFTP-профиль на тот же адрес и проверьте, что они не предлагают эти данные. Экспортируйте JSON, проверьте отсутствие пароля, приватного ключа, ссылки на vault и токена. Импортируйте файл в чистый профиль приложения два раза. Во второй раз число добавленных профилей должно быть нулём.
7. Повторите действия с RU и EN, светлой и тёмной темой и масштабом Windows 100%, 125%, 150% и 175%. Сузьте окно, откройте панель деталей и проверьте доступность кнопок, горизонтальной панели действий и списка.

## Результаты локальной проверки

| Проверка | Результат |
| --- | --- |
| Flutter 3.24.5, полный набор `flutter test --no-pub` | 48 прошли, 16 тестов с внешними fixtures пропущены обычным запуском |
| Изолированный OpenSSH, базовые SSH-проверки | 4 прошли, 5 требуют полноценного системного fixture |
| SFTP и запуск из каталога через реальный OpenSSH | 8 тестов существующего SFTP-набора и 2 интеграционных сценария запуска SSH/SFTP прошли |
| Форматирование и статический анализ затронутой области | Dart и Rust форматированы. В модулях YES Desk замечаний нет. Анализ файлов навигации вывел 11 прежних информационных замечаний |
| Генерация Flutter Rust Bridge и `flutter build bundle --debug --no-pub` | Успешно. Для локального libclang 19 указан путь к системным заголовкам через `C_INCLUDE_PATH` |
| Полный `flutter analyze --no-pub` | Завершился с прежним предупреждением об импорте и 6 информационными замечаниями в `lib/web` |
| GitHub Actions | GitHub ответил HTTP 422 при вызове существующего workflow. Actions отключены в настройках репозитория, у Draft PR нет запущенных проверок |

Полный SSH-fixture с системным пользователем не запустился в локальном контейнере из-за нехватки диска при установке OpenSSH и Python. Интерактивный запуск нативной RustDesk-сессии, штатный MSTSC, Windows Credential Manager и реальный Windows DPI остаются шагами desktop-проверки.
