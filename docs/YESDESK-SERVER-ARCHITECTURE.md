# Серверная архитектура YES Desk

Подтверждённый состав развёртывания включает **RustDesk OSS Server 1.1.15** (`hbbs` и `hbbr`), **lejianwen/rustdesk-api v2.7**, Nginx reverse proxy, Docker Compose и Ubuntu 24.04 LTS. Административная веб-панель закрыта намеренно. Данные развёртывания хранятся в инфраструктуре организации.

## Разделение сервисов

| Компонент | Ответственность |
| --- | --- |
| `hbbs` | Регистрация устройств и согласование соединения |
| `hbbr` | Передача трафика через ретранслятор при выбранном relay |
| `rustdesk-api` | Вход в учётную запись, адресные книги, доступные устройства и поддерживаемые API события |
| Nginx | Существующая внешняя точка входа для разрешённых HTTP-маршрутов |
| Docker Compose | Управление контейнерами и жизненным циклом сервисов |

Клиент продолжает использовать штатные FFI, модели аккаунтов и адресной книги, настроенные серверы и ключи. Наличие API само по себе не обеспечивает запрет входящих либо исходящих сессий на OSS hbbs. Документация v2.7 отдельно указывает, что принудительный вход перед соединением относится к специальному форку сервера. В нашей архитектуре указаны официальные OSS hbbs/hbbr. [RustDesk Server 1.1.15](https://github.com/rustdesk/rustdesk-server/releases/tag/1.1.15) · [Примечание rustdesk-api v2.7](https://github.com/lejianwen/rustdesk-api/blob/v2.7/README_EN.md#better-used-with-lejianwenrustdesk-server)

## API v2.7

Рассмотрен тег `v2.7` с коммитом `222792419f8b55c17b36bf5f423ec5ed7a53e2c4`. Таблица описывает реализацию релиза. Доступность возможностей через действующее развёртывание требует проверки на тестовом стенде. [Тег v2.7](https://github.com/lejianwen/rustdesk-api/releases/tag/v2.7)

| Возможность | Реализация в теге |
| --- | --- |
| Аккаунт | `GET /api/login-options`, `POST /api/login`, `POST /api/currentUser`, `POST /api/logout` |
| Дополнительный вход | OIDC и OAuth через соответствующие маршруты. В документации версии указаны Google, GitHub, OIDC и опциональный LDAP |
| Адресная книга | Базовые `GET/POST /api/ab`. Отдельные маршруты для личных и общих профилей, устройств и тегов |
| Группы | `GET /api/device-group/accessible`, `GET /api/users`, `GET /api/peers` под клиентской авторизацией |
| Heartbeat и аудит | `/api/heartbeat`, `/api/sysinfo`, `/api/audit/conn`, `/api/audit/file` |
| Web client и Swagger | Регистрируются при соответствующих опциях версии. Административная панель в нашем развёртывании закрыта |

Порядок регистрации маршрутов и middleware виден в исходниках версии. Проверку фактического набора доступных функций следует вести через текущий клиент и разрешённые тестовые аккаунты, включая ошибки авторизации и недоступные маршруты. [Клиентский маршрутизатор v2.7](https://github.com/lejianwen/rustdesk-api/blob/v2.7/http/router/api.go) · [Swagger из тега](https://github.com/lejianwen/rustdesk-api/blob/v2.7/docs/api/api_swagger.yaml)

Sprint 1 проверен пользователем на запуске MSI, подключении нового клиента к старому, видео и буфере обмена. Relay, настройка сервиса, первоначальная авторизация, общие книги, группы и права требуют отдельной проверки. SSH и SFTP в будущих спринтах устанавливают прямые SSH-соединения независимо от этого стека.
