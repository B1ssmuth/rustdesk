# YES Desk Unified Connection Manager

«Мои подключения» — личный каталог настольного YES Desk. Быстрое подключение, недавние устройства, избранное RustDesk, адресные книги и прочие разделы удалённого доступа по-прежнему доступны. SSH / SFTP и Windows RDP сохраняют свои рабочие области.

## Источники и идентичность

| Источник | Подключение к каталогу |
| --- | --- |
| RustDesk | Адаптер читает сохранённые peers и недавние записи через существующий Flutter bridge и объединяет их с избранным по точному ID. Для старых недавних запись получает время изменения peer-файла, которое использует и нативное упорядочивание. У избранного без peer-файла время неизвестно. |
| SSH | `SshRepository` остаётся источником профилей, связанных ссылок на хранилище учётных данных и групп. Каталог отображает существующие группы как папки первого уровня, в том числе пустые. |
| SFTP | В базовой версии отдельного файла SFTP-профилей нет. Действие «Открыть SFTP-сессию» из существующего SSH-профиля сохранено. Новые выделенные профили SFTP записываются в тот же репозиторий с признаком `filesOnly`, который отсутствует у legacy-записей. |
| Windows RDP | `RdpProfileStore` по-прежнему владеет параметрами MSTSC и сохраняет исходный формат. |
| Личный каталог | `connections/catalog.json` содержит профили Remote Desktop, пользовательские папки и метаданные. Вложенность задаётся ссылками на UUID родителя. Проверка проходит по цепочке итеративно и отклоняет циклы и отсутствующих родителей. |

Legacy UUID вычисляются из пространства имён источника и его идентификатора. Простое открытие каталога не переписывает legacy-профили. При сохранении изменений каталожный UUID закрепляется до записи SSH/RDP-профиля, при повторе используется тот же ключ. Каталог сериализует операции и записывает свой файл через временный файл и переименование. SSH/RDP и метаданные остаются разными файлами. После сбоя между двумя записями успешно записанный транспортный профиль остаётся доступным по закреплённому UUID. Импорт предварительно проверяет структуру, добавляет отсутствующие UUID и сохраняет профили по одному. При ошибке записи уже сохранённые профили остаются доступны. Повторный импорт пропускает завершённые записи и дозаписывает метаданные зарезервированных записей.

Изменения имени, адреса и параметров SSH/SFTP/RDP записываются в исходные репозитории. Папки каталога и плоские группы SSH имеют отдельную структуру. Исходная SSH-группа сохраняется в SSH / SFTP, а перемещение в каталоге меняет только положение в каталоге. Профили Remote Desktop, созданные в каталоге, и пользовательские правки импортированных peers хранятся в личном каталоге. Удаление из него не стирает native peer-файл, историю или избранное RustDesk. Метка скрытия предотвращает повторное появление записи при следующем чтении native-данных. Даты создания и изменения legacy-профилей могут отсутствовать до первой правки через каталог.

## Запуск, состояние и учётные данные

`ConnectionLauncher` маршрутизирует типизированные настройки в существующие точки запуска. Remote Desktop вызывает `connect`, SSH и SFTP открывают `SshWorkspaceState.openProfile`, Windows RDP запускает `RdpLauncher`. Навигация сохраняет смонтированными открытые рабочие области, закрытие панели деталей не закрывает сессии.

- Для Remote Desktop отображаются открытые вкладки из действующего оконного менеджера. Вкладка может ожидать авторизацию. Отдельно доступный RustDesk-статус присутствия остаётся в native-разделе.
- SSH/SFTP отображают фазы реальной сессии. История отмечает успешное подключение, в том числе из существующей рабочей области. Запуск SFTP как подсистемы уже открытой SSH-сессии сохраняет существующее поведение.
- Для RDP учитывается время запуска и время жизни локального процесса MSTSC. Windows может передать подключение другому процессу, а сетевой статус доступен в клиенте Windows.
- Профили SSH и SFTP имеют независимые ключи в репозитории и ссылки на Windows Credential Manager. При отдельном запуске SFTP из legacy SSH-профиля его сохранённые учётные данные не предлагаются и ссылка на vault не создаётся. При изменении адреса, порта, пользователя или способа аутентификации исходный репозиторий проверяет, можно ли сохранить существующую ссылку. Дублирование создаёт новый профиль без ссылки.
- Экспорт версии 1 использует явный список полей. Из него исключены ссылки на vault, ключи, пароли, SSH-комментарии и данные доверия к хостам. Настройки регистрации и учётные данные RustDesk и MSTSC остаются у их штатных механизмов. Для новых записей каталог принимает обычные ID и адреса без query-параметров. Ключ сервера, который пришёл в legacy-адресе RustDesk, передаётся только в его штатный запуск. Такие адреса пропускаются при экспорте, а их ключи отсутствуют в каталожном файле.

## Корпоративный каталог

`PersonalConnectionsProvider` и `CorporateDevicesProvider` — независимые контракты. Корпоративная модель имеет идентификатор сервера и список разрешённых транспортов. Сервер будет владеть правилами доступа и жизненным циклом. Никакая часть личного каталога не создаёт, не импортирует и не сопоставляет корпоративные записи.
