# Sprint 3.6 · Admin UI and first pilot

## Подготовка Management API

В существующем **Management** Compose сохраните образ API и рабочие переменные, сделайте проверяемый backup PostgreSQL 17.9 и прогоните обновление на резервной копии базы. После отдельного согласования оператор выполняет в каталоге Management Compose:

```bash
docker compose build api migrate
docker compose run --rm --no-deps migrate
docker compose up -d --no-deps api
curl -fsS http://127.0.0.1:18083/health/ready
```

Миграция `006_admin_pilot.sql` добавляет отметку ожидающего сброса MFA. Миграции `001–005` сохранены. Действующая учётная запись admin и ключ `YESDESK_MFA_KEY_FILE` используются повторно. При откате восстановите предыдущий образ API и его конфигурацию. Добавленный совместимый столбец можно сохранить. Подробности резервного копирования приведены в [Simple Enterprise](SIMPLE-ENTERPRISE.md).

## Клиент и вход

Пример `enterprise/client-config.example.json` использует `https://desk.yesapart.com/management` как **предлагаемый** HTTPS-префикс. Перед сборкой оператор подтверждает доступный извне адрес. При префиксе `/management` одобренный reverse proxy должен передавать `/management/v2/…` в `127.0.0.1:18083/v2/…`, удаляя только префикс. Существующие правила RustDesk оставьте без изменений. Готовность маршрута в действующей инфраструктуре здесь не проверялась. Используйте доверенный сертификат на фактическое DNS-имя и не записывайте Authorization или тела запросов.

```powershell
pwsh -File .\scripts\build-windows-local.ps1 -Build -BridgeMode Native -Ref HEAD -EnterpriseConfig .\enterprise\client-config.example.json
```

Отправьте подтверждённый адрес в конфигурации через `YESDESK_MANAGEMENT_URL`. Клиент проверяет сертификат TLS, работает со штатным проверяющим хранилищем и передаёт серверный токен как Bearer. Обычный доступ по RustDesk ID не требует настройки Management URL.

Войдите в **Настройки → Аккаунт → Администрирование → Пользователи** под admin. Проверьте создание, поиск, редактирование имени и роли, блокировку, разблокировку и отзыв. Первоначальный пароль передаётся сотруднику через защищённый канал. Принудительная смена при первом входе отсутствует. Смену можно выполнить из настроек. Для новой admin или support включите MFA через серверную команду `reset-mfa` до первого входа.

Запрос сброса MFA требует текущего пароля администратора и нового кода TOTP. Он отзывает сеансы пользователя и оставляет статус «Ожидается сброс». Оператор отдельно сверяет личность сотрудника и в приватном терминале выполняет `docker compose exec api python local_auth.py reset-mfa USERNAME`. Новый пароль и первоначальный ключ передаются отдельно по защищённому каналу. UI и API администрирования не возвращают MFA-секрет.

## Один тестовый Windows ПК

1. Используйте изолированную тестовую VM. Проверьте HTTPS-адрес лабораторного Management API, который запущен с `YESDESK_WINDOWS_AGENTS=1`. Сверьте SHA-256 установщика агента. Для GPO после пилота используйте подписанный MSI.
2. Соберите паспорт устройства с `id` (MachineGuid), `computer_sid` (локальный SID машины из доверенной инвентаризации), `hostname`, `dns_name` и `yesdesk_id`. Оператор сверяет GUID и YES Desk ID. Через временно доступный для контейнера защищённый JSON и приватный терминал выполните `docker compose exec api python provision.py enroll-windows-device /secured/device.json`. Код действует десять минут и используется однократно.
3. В повышенной PowerShell 7.2+ выполните `pwsh -File .\enterprise\agent\Provision-Agent.ps1 -Api https://management.lab.example`, подставив реальный лабораторный URL. Введите индивидуальный код в скрытом приглашении.
4. Установите `msiexec.exe /i YESDesk-Agent-x64.msi /l*v agent-install.log`. Через `Get-Service YESDeskAgent` проверьте состояние службы, затем найдите ПК в каталоге и проверьте heartbeat, модель, RAM, диски и текущего Windows-пользователя. Проверьте запуск после перезагрузки, второй интерактивный/RDP-сеанс и восстановление связи после временного отключения тестового API.
5. Проверьте отказ повторного enrollment с тем же кодом. Проверку отзыва выполняйте в лаборатории через `POST /v2/devices/{uuid}/revoke-agent` с административным Bearer. Устройство остаётся в каталоге с состоянием «Агент отсутствует». Старый токен и ожидающий код отзываются. Для повторной привязки используйте процедуру ротации и новый индивидуальный код.
6. Удалите агент командой `msiexec.exe /x YESDesk-Agent-x64.msi /l*v agent-uninstall.log` и проверьте отсутствие службы. Защищённый каталог состояния сохраняется при удалении MSI для повторной установки. Перед передачей или списанием машины отзовите серверный токен и удалите состояние по принятой процедуре. Массовая установка MSI по GPO пока требует отдельной безопасной выдачи индивидуальных кодов.

Пакеты пилота не меняют существующие условия авторизации RustDesk. Из каталога доступна проверка политики, а корпоративный запуск остаётся запрещён HTTP 501 до проверки на получателе и подтверждения сотрудником. Unattended запрещён.
