# Переход YESSPB-006 на единый Enterprise MSI

В этой сборке переход поверх действующего RustDesk или отдельного YESDeskAgent заблокирован. Регистрируемый единым MSI транспорт называется `YES Desk`, а upstream-служба называется `RustDesk`. Установщик теперь обнаруживает upstream-службу непосредственно через SCM-ветку реестра. Регистрация отдельного MSI агента также проверяется по UpgradeCode, даже если самой службы уже нет.

## Локальный Preflight

Войдите в физическую консоль YESSPB-006 под администратором. В Windows PowerShell 7 x64 выполните проверку из копии поставки.

~~~powershell
pwsh -NoProfile -File C:\Pilot\enterprise\pilot\Preflight-YESSPB006.ps1
~~~

Скрипт читает сведения о службах, версии их EXE, регистрации продуктов, свойства MSI из доступного локального кэша, наличие файлов профилей и отпечатки сертификатов. Значение `null` означает, что соответствующий каталог недоступен для чтения. Скрипт выводит JSON в консоль. Содержимое TOML и токенов, закрытые ключи и аргументы запуска служб в отчёт не входят. На целевой машине нужны фактические ProductCode и оригинальные пакеты с доверенными хешами.

| Тип | UpgradeCode |
| --- | --- |
| YES Desk MSI, в том числе Enterprise | `{1A8AC87B-B936-5AA9-AE11-219B6D3A8B59}` |
| Upstream RustDesk и некоторые старые пакеты YES Desk | `{D3DC41E3-3C37-5D52-BB47-F6673705C01B}` |
| Отдельный YESDeskAgent | `{4250C5DB-5E09-44AB-816C-4082BB30DEB6}` |

UpgradeCode идентифицирует семейство. Для определения владельца службы сверяйте ProductCode, производителя, версию EXE, команду SCM из первичного источника, учётную запись и кэшированный пакет. Старый пакет может создавать службу через CustomAction, поэтому отсутствие строки ServiceInstall не доказывает отсутствие владельца.

## Почему автоматический переход заблокирован

- Транспортная идентичность хранится в основном TOML. Она включает `enc_id` и пару ключей. При ошибке расшифровки текущий клиент может сгенерировать другой ID. Расшифровка использует идентификатор машины. Простое копирование на другой ПК или в другой профиль не подтверждает совместимость.
- Текущее имя приложения определяет каталоги и имена TOML. Текущая сборка использует `AppData\Roaming\com.yesapart\YES Desk\config`. Код Windows может перенаправить путь SystemProfile в профиль LocalService. У старого RustDesk возможны другие имя и расположение. Нужно подтвердить фактически читаемые профили службы и всех участвующих пользователей. Файл с суффиксом `2.toml` содержит отдельные параметры транспорта.
- Агент хранит состояние в `%ProgramData%\YESDeskAgent`. Токен зашифрован DPAPI LocalMachine. Сертификаты и закрытые ключи остаются в хранилище LocalMachine. Новый MSI не должен перерегистрировать успешно работающий агент. Отдельный MSI и Enterprise владеют компонентом YESDeskAgent под разными GUID. Если оставить старую регистрацию и запустить новый MSI поверх неё, будущий uninstall старого MSI может удалить службу или её EXE.
- В исходном RustDesk удаление может выполнять собственный CustomAction остановки и удаления службы. Транзакция нового MSI не сможет автоматически восстановить неизвестные эффекты неподтверждённого старого деинсталлятора. Текущий `--import-config` условно копирует файлы по временам изменения. Он не заверяет сохранение ID, ключей либо правильного служебного профиля.

## Порядок подготовки установки

1. Сохраните Preflight и независимый образ исходного ПК с проверяемым восстановлением. Зафиксируйте версии и фактические ProductCode обоих владельцев, один исходный ID `54787641`, публичный ключ транспорта, адреса hbbs/hbbr, стартовые параметры служб и состояние агента.
2. Проверьте SHA-256 и статус подписи MSI. Создайте резервную копию из локального сеанса на YESSPB-006.

~~~powershell
$root = 'C:\Pilot'
$msi = Join-Path $root 'YES_Desk-Enterprise-1.4.6-x86_64.msi'
Get-FileHash -LiteralPath $msi -Algorithm SHA256
Get-AuthenticodeSignature -LiteralPath $msi | Select-Object Status
& "$root\enterprise\pilot\Prepare-YESSPB006.ps1" -Msi $msi `
    -BackupDirectory "$root\backup-endpoint"
~~~

3. Убедитесь, что резервная копия охватывает служебный профиль, пользовательские профили, ProgramData агента, ACL, MachineGuid и закрытые ключи сертификатов через образ исходного ПК или штатный PKI-процесс. Скрипт сохраняет копии конфигурации и сведения о сертификатах. Для окончательной копии нужна остановка приложений по согласованному плану, с локальным доступом к консоли.
4. На изолированной восстановленной копии воспроизведите те же версии и ProductCode. До снятия блокировки нужен проверенный перенос профилей и владения службами. Проверьте читаемость `enc_id`, совпадение публичного ключа, параметры hbbs/hbbr, сохранение токена агента и ACL. Используйте тестовую сеть, независимые сертификаты и контролируемые hbbs/hbbr. В корпоративной сети копию с тем же ID не запускайте.
5. Испытайте чистую установку, обновление воспроизведённой конфигурации, повтор того же MSI, ошибку после остановки первой службы и откат. Сверьте службы, версии, ID и публичный ключ транспорта, heartbeat агента, параметры профилей и работу после перезапуска. Текущий MSI предназначен для чистой установки и в п. 4 блокирует обновление. На действующем YESSPB-006 остановитесь после подготовки.

## Откат

При блокировке LaunchCondition штатная установка до замены служб не доходит. Сверьте исходные службы и запуск в журнале MSI. Ничего не удаляйте. Для будущей согласованной миграции основной способ отката — проверенное восстановление образа исходного ПК. Оно возвращает обе регистрации MSI/SCM, профили, ACL и состояние DPAPI в одном состоянии. Отдельный ручной откат требует исходных пакетов и доказанной процедуры. Восстановите приложение, остановите обе службы, верните соответствующие профили на исходные пути, затем проверьте запуск, ID, ключ, hbbs/hbbr и heartbeat. Не отзывайте серверную регистрацию ради локальной миграции. Повторная регистрация уместна только при утрате или отзыве токена.

Самостоятельный локальный тест условий запуска использует ограниченную сессию Windows Installer. Он проверяет реакции на признаки чистой машины, конфликтов и повторного запуска. Установка и транзакционный откат в этой проверке не выполняются. [Документация ограниченной сессии MSI](https://learn.microsoft.com/windows/win32/api/msi/nf-msi-msiopenpackageexa)
